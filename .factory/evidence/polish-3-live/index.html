HOW IT WORKS

Scrub and package an incident log.

  1. 01

    Collect locally

    Point one command at files or directories.

  2. 02

    Scrub consistently

    The same value gets the same replacement within one casefile.

  3. 03

    Create the encrypted ZIP

    A casefile is an AES-256 encrypted ZIP with rule names and counts, not matched values.

CLEAR LIMITS

Limits of rule-based log scrubbing.

Rules cannot find every secret or identifier. Review the casefile before sharing. This is not a log host or cloud scrubber.

{
  "format": "scrubbed-log-casefile",
  "rule_hits": {
    "email": 14,
    "credential-assignment": 3
  },
  "token_scope": "this archive"
}

VERSION 0.1.3 / MIT

Build one local binary.

Run the bundled sample first, then pack your own incident files.

BUILD + DEMO
cargo install --git https://github.com/B-Divyesh/sf-scrubbed-log-casefile
casefile demo
export CASEFILE_PASSWORD='a-long-unique-passphrase'
casefile pack ./incident --output vendor.casefile.zip
casefile inspect vendor.casefile.zip --extract

Password stays out of arguments.
Read it from CASEFILE_PASSWORD or another variable.

A failed run leaves no partial casefile.
Existing output remains unless you pass --force.

Review before sharing.
casefile inspect shows the manifest and can extract scrubbed files into a new temporary directory.
